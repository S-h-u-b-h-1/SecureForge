# Local Muse qualification evidence

The parent `live-model-qualification.json` records actual model session IDs, task prompts, source hashes, failed candidates, measured feedback and final saved-output results. `task-a-passport.json` and `task-b-passport.json` were exported by the actual Passport code. Their built-in actor label does not establish a human click: staging, hunk and command approvals were supplied explicitly by the test harness.

Generation used the real local TrueForge SDK/MCP bridge and configured Muse model. Apply, Save and guarded Undo used desktop VS Code APIs. Each task used a separate disposable Flask checkout pinned to `22d924701a6ae2e4cd01e9a15bbaf3946094af65` and a separate Python 3.12 environment with that checkout installed editable and pytest 8. The acceptance tests assert that Flask imports from the checkout under test. After tests, Undo and Save restored all original tracked source bytes.

- Task A: 20 independent acceptance tests passed on the saved model output.
- Task B: 62 tests passed, comprising the existing/generated CLI suite and independent acceptance checks. This required measured failure feedback about JSON serialization of the default `timedelta` value. An earlier candidate had 60 passing and 2 failing tests; its failed outcome is retained in the parent report.
- The source proposals were not manually repaired. The final B implementation, tests and documentation were generated by Muse after the recorded feedback. Full source bodies, private provider configuration and API keys are excluded from these shared artifacts.

To rerun an acceptance test, copy the corresponding file from `acceptance/` into the disposable Flask checkout's `tests/` directory after saving a reviewed model proposal. Invoke it with that checkout's Python environment. For B, run both `tests/test_cli.py` and the copied independent test. The tests are separate from the candidate's own generated tests.

`npm run test:wire` is a different check: it uses deterministic local inference with the real runtime to verify full source delivery and both proposal transports. It incurs no model-provider inference request. `npm run test:editor:wire` adds packaged editor integration checks when a local TrueForge runtime and desktop VS Code are available.

Interactive normal Build/Inline approval dialogs and review button clicks with a real model remain unqualified because native accessibility automation timed out. The API harness is not presented as evidence of those interactions. Video/PDF and portal submission are outside this work.
